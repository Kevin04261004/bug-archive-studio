# Bug Archive Studio

버콜의 코드 퀴즈 쇼츠를 동일한 디자인으로 생성하는 자동 제작 도구입니다.
화면 문구는 영어이며, 1080×1920 / 30fps / 12초 MP4를 출력합니다.

## 가장 쉬운 사용법 — Windows

1. 이 ZIP을 한 폴더에 압축 해제합니다.
2. Python 3.10 이상을 설치한 상태에서 `SETUP.bat`을 한 번 실행합니다. 인터넷 연결이 필요합니다.
3. `episodes/CS1002.json`을 복사한 뒤 내용과 `bug` 이미지 경로를 변경합니다.
4. JSON 파일을 `RENDER.bat` 위로 드래그합니다.
5. `output` 폴더의 MP4를 유튜브에 업로드합니다.

`RENDER.bat`을 그냥 실행하면 포함된 CS1002 예제가 생성됩니다.
`RENDER_ALL.bat`은 episodes 폴더의 JSON을 이름순으로 모두 제작합니다.
Python 실행 명령이 `python`인 PC에서는 아래 터미널 명령을 사용하면 됩니다.

## 바꾸는 것

`episodes/CS1002.json` 예제를 기준으로 다음 필드만 바꾸세요.

| 필드 | 의미 |
|---|---|
| error_code | CS1002 형태의 실제 오류번호 |
| message | 실제 영어 컴파일러 오류 메시지 |
| before | 오류가 있는 코드. 한 줄당 배열 원소 하나 |
| after | 수정한 코드. 한 줄당 배열 원소 하나 |
| bug | 이 JSON 위치에서 상대 경로로 지정한 투명 PNG |
| filename | 코드 패널의 파일 이름. 생략 시 Player.cs |
| focus_line | 여러 수정 위치 중 포획이 시작될 행 번호. 선택, 1부터 |
| music | 배경음 파일 이름, `random`, 또는 `none`. 생략하면 random |

기본 배경, 버콜, 타이밍, 효과음, 포획 동선, 도감 디자인은 바꿀 필요가 없습니다.
버그 이미지는 AI 생성 또는 PNG 교체로 지정합니다. 한 번 지정하면 비행·포획·가방 수집·도감 실루엣·해금 이미지에 모두 적용됩니다.
이미지에 버그 이름이나 오류번호를 새겨 넣을 필요는 없습니다. 코드와 문구는 별도로 정확하게 조판됩니다.

## 에피소드 만드는 규칙

에피소드는 **컴파일러 최소 재현 코드가 아니라 사람이 실제로 저지르는 실수**여야 합니다.
판정 기준과 이름 규칙, 맥락 고르는 법은 `EPISODE_STYLE.md`에 정리해 두었습니다.
새 에피소드를 쓰기 전에 그 문서를 먼저 읽으세요.

조판이 어긋나지 않게 하는 기계적 규칙은 이렇습니다.

- 코드는 **10~20줄**입니다. 10줄 밑은 맥락이 없어 "왜 저렇게 썼지"가 성립하지 않고,
  20줄을 넘으면 진단 줄이 진행자 스프라이트를 덮습니다.
- `before`와 `after`의 줄 수를 맞춥니다. 줄을 새로 끼워 넣으면 이후 모든 행이 diff로
  잡혀 화면이 지저분해집니다. 중괄호나 지시문을 지우는 수정은 그 자리를 빈 줄로 남깁니다.
  using을 추가하는 CS0246도 기존 using을 고치는 형태로 맞췄습니다.
- 수정은 한 곳만 둡니다. 그 위치를 오류 토큰 자체에 두면 빨간 물결선이 그 아래에
  정확히 놓입니다.
- `focus_line`은 실제로 바뀌는 행 번호입니다.
- 오류 메시지는 진단 줄과 도감 카드 양쪽에서 두 줄 안에 접혀야 합니다. 대략 90자가
  한계입니다. 실제 컴파일러 문구의 앞부분을 살리고 괄호 안 부연을 줄이면 대부분 들어갑니다.
- 코드 한 줄은 **38자 이하**를 권합니다. 44자가 하드 리밋이고, 넘으면 26px 밑으로
  떨어져 렌더러가 거부합니다. 선언이 길면 `where` 절이나 메서드 본문, 람다 본문을
  다음 줄로 내리세요.
- 버그 PNG가 아직 없으면 액션은 그 에피소드를 건너뛰고 넘어갑니다. 나중에
  `assets/<오류번호>.png`를 커밋하면 그 커밋이 렌더를 시작합니다. 에피소드 JSON을
  먼저 올려 두어도 빨간 실패가 남지 않습니다.

### 검증

```
python3 tools/validate_episodes.py
```

렌더러와 같은 식으로 글자 크기와 레이아웃을 계산해 위 규칙을 전부 검사합니다.
`class A`, `void M()`, `foo` 같은 실험실 코드 냄새도 함께 잡습니다.
`--strict`를 붙이면 경고도 실패로 취급합니다.

리라이트를 여러 편 한꺼번에 적용할 때는 `tools/batches/`의 배치 스크립트를 쓰고
`python3 tools/apply_batch.py <배치>.json`으로 반영합니다. 버그 PNG 경로와 음악
설정은 그대로 유지됩니다.

## 버그 PNG 크기

버그 이미지는 `assets/<오류번호>.png` 한 장입니다. 렌더러가 이 그림을 가장 크게 쓰는 곳은
LOCKED 썸네일의 실루엣으로 높이 760px 정도이고, 도감 카드에서는 275px입니다. 그래서 원본을
그보다 크게 둘 이유가 없습니다.

페이지에서 버그를 넣으면 긴 변 800px로 맞춰 저장합니다. 이건 단순한 용량 문제가 아닙니다.
깃허브 페이지는 **커밋마다 저장소 전체를 빌드 아티팩트로 묶기** 때문에, `assets/`가 무거우면
푸시 한 번마다 그만큼이 액션 저장소 사용량으로 쌓입니다. 1MB짜리 PNG로 506개를 채우면
푸시마다 500MB가 됩니다.

손으로 PNG를 넣을 때도 800px 안쪽으로 줄여서 넣으세요.

## 에피소드 목록 현황

`cs-error-series-checklist.md`의 537개 항목 중 506개가 `episodes/`에 들어 있습니다.
나머지 31개는 이 형식으로 정확하게 표현할 수 없어 뺐고, 그 목록과 이유는 체크리스트 맨 아래에
적어 두었습니다. 대부분 프로젝트 설정·어셈블리 참조 단계의 오류라 화면에 보여줄 소스 코드가 없습니다.

에피소드 JSON 506편은 전부 위 규칙을 통과한 상태입니다(`tools/validate_episodes.py` 오류 0).
한 줄만 바뀌고, 바뀐 자리가 오류 토큰이며, 가장 긴 코드 줄이 26px에서도 704px 안에 들어가고,
메시지가 진단 줄과 도감 카드 양쪽에서 두 줄 안에 23px 이상으로 접힙니다.
문제를 풀 때 필요한 선언은 전부 화면 안에 보입니다.

506편 모두 10~20줄의 유니티·콘솔 앱 맥락으로 다시 썼습니다. 예전에는 대부분이 4~5줄짜리
최소 재현 코드였는데, 맥락이 없으면 "누가 저렇게 써"가 되어 시청자가 넘깁니다.

## 깃허브 페이지에서 쓰기

이 폴더를 그대로 깃허브 페이지로 올리면 브라우저만으로 편집할 수 있습니다.
저장소 설정의 Pages에서 `main` 브랜치 루트를 지정하면 됩니다.

페이지에서 되는 것은 에피소드 편집, 에피소드 불러오기, 여러 편 한꺼번에 렌더, AI 버그 생성,
LOCKED 썸네일 저장, 프로젝트 JSON 저장입니다. 헤더에 `WEB EDITOR`로 표시됩니다.

MP4는 어느 경우에나 `render.py`가 만듭니다. 페이지에서는 **Render MP4** 한 번으로 끝납니다.
페이지가 에피소드 JSON과 버그 PNG를 저장소에 커밋하고, 액션에서 `render.py`를 실행한 뒤,
완성된 MP4를 그대로 내려받습니다. 보통 2분 안쪽입니다.

처음 한 번만 깃허브 토큰을 붙여넣으면 됩니다. 이 저장소만 대상으로 하는 fine-grained 토큰에
**Contents**와 **Actions**를 read and write로 주세요. 토큰은 이 탭에만 남고 api.github.com으로만 갑니다.
토큰 없이 쓰려면 **Render MP4** 대화창의 **Save project**로 JSON을 받아 직접 커밋해도 되고,
내 PC의 `START_STUDIO.bat`을 써도 됩니다.

에피소드 목록은 `episodes/index.json`을 읽습니다. 스튜디오를 켜거나 렌더할 때,
그리고 액션이 돌 때 자동으로 갱신됩니다. 직접 만들려면 `python server.py --index`를 실행하세요.

## 페이지 파일을 고칠 때

`index.html`은 `studio.css?v=3.5`, `studio.js?v=3.5`처럼 버전을 붙여 읽습니다.
**둘 중 하나라도 고치면 두 곳의 숫자를 함께 올리세요.** 올리지 않으면 브라우저와
깃허브 페이지 CDN이 예전 파일을 계속 주고, 새 HTML의 버튼은 보이는데 눌러도
아무 일이 일어나지 않습니다.

## 여러 편 한꺼번에 렌더

헤더의 **Batch render** 버튼을 누르면 에피소드 목록이 체크 목록으로 열립니다.
원하는 줄을 눌러 고르고 **Render selected**를 누르면 전부 한 번에 만들어집니다.

- **티어 제목을 누르면 그 티어 전체가 선택됩니다.** 다시 누르면 전부 풀립니다.
  제목 오른쪽의 `12 / 34`가 그 티어에서 몇 개를 골랐는지 보여주고, 전부 고르면 제목이 연두색이 됩니다.
  선택할 수 있는 항목이 하나도 없는 티어(버그 PNG가 아직 없는 티어)는 눌리지 않습니다.
- 위쪽 칸에 오류번호나 파일 이름, 메시지 일부를 치면 목록이 걸러집니다.
  **Select all**과 티어 제목은 그때 화면에 보이는 것만 고르므로, 필터와 같이 쓰면
  "3티어 중 Player.cs만" 같은 선택도 두 번의 클릭으로 됩니다.
  필터를 바꿔도 이미 고른 것은 풀리지 않습니다.
- 버그 PNG가 아직 없는 에피소드는 회색으로 비활성입니다. 렌더러가 건너뛰는 항목이라 고를 수 없습니다.
- 고른 것들은 **한 번의 액션 실행**으로 처리됩니다. 한 편씩 누르면 러너를 매번 새로 기다리는데,
  서른 편이면 대기 시간이 렌더 시간보다 길어집니다.
- 한 편이 실패해도 나머지는 그대로 올라갑니다. 실패한 것은 목록에 이유와 함께 표시됩니다.
- 두 편 이상이면 끝났을 때 **ZIP 하나**가 자동으로 내려받아집니다. 아래에 한 편씩 받는 링크도 남습니다.

### ZIP으로 유튜브에 한꺼번에 올리기

압축을 풀면 이렇게 들어 있습니다.

```
C# QUIZ - ERROR CS0103.mp4
C# QUIZ - ERROR CS0246.mp4
thumbnails/C# QUIZ - ERROR CS0103.png
titles.tsv
```

영상은 맨 위에, 썸네일은 한 단계 아래에 둡니다. 압축을 푼 폴더에서 **전체 선택하면 그대로 영상만**
잡히므로 유튜브 스튜디오 업로드 창에 통째로 끌어다 놓으면 됩니다. 제목은 파일 이름에서 자동으로
채워집니다. 나머지(설명·태그·재생목록·공개 범위)는 올린 뒤 스튜디오에서 여러 개를 선택해
**일괄 편집**으로 한 번에 지정하세요. `titles.tsv`는 그때 붙여 넣을 내용을 표로 담고 있습니다.

ZIP으로 주는 이유는 두 가지입니다. 깃허브는 릴리스 자산 이름의 문자를 바꾸지만 **ZIP 안의 이름은
건드리지 않아서** `C# QUIZ - ERROR CS0103.mp4`가 그대로 살아남습니다. 그리고 서른 편이면
브라우저가 연속 다운로드를 막는데, ZIP은 한 번에 끝납니다.

배치 ZIP은 `batch-<실행번호>` 릴리스에 붙고 최근 다섯 개만 남습니다. 다시 받으려면 배치를
다시 실행하면 됩니다.

배치는 **저장소에 이미 들어 있는 JSON**을 렌더합니다. 편집기에서 고치던 내용은 들어가지 않으니,
방금 고친 에피소드는 먼저 **Render MP4**로 저장한 뒤 배치에 넣으세요.

내 PC에서 `START_STUDIO.bat`으로 열었을 때도 같은 버튼이 동작합니다. 이 경우는 `output` 폴더에
바로 쌓입니다.

## 에피소드 불러오기

헤더의 **Load episode** 버튼에서 `episodes` 폴더의 JSON 목록을 바로 볼 수 있습니다.
목록은 `cs-error-series-checklist.md`의 순서 그대로 나오고 티어별로 나뉩니다. 각 줄 왼쪽의 숫자가 체크리스트 번호입니다.
번호가 건너뛰는 자리는 그 항목을 제외했다는 뜻입니다. 제외 목록은 체크리스트 맨 아래에 있습니다.
오류번호, 파일 이름, 줄 수, 오류 메시지가 함께 표시되고, 항목을 누르면 에디터에 채워집니다.
JSON의 `bug` 경로가 가리키는 PNG도 함께 불러와 미리보기에 적용합니다.
그 PNG가 아직 없으면 목록에 `no bug PNG`로 표시되고, 불러오면 버그 이미지가 **빈 상태**가 됩니다.
Render MP4와 썸네일 저장이 잠기고, 미리보기에도 캐릭터가 나오지 않습니다. 직전 에피소드의 이미지를
그대로 물려주면 렌더할 준비가 된 것처럼 보이지만, 실제로는 남의 PNG가 이 오류번호로 커밋됩니다.
**Generate bug with AI** 나 **Replace bug** 로 이미지를 넣으면 바로 다시 풀립니다.

`START_STUDIO.bat`으로 열면 폴더를 직접 읽고, 깃허브 페이지에서는 `episodes/index.json`을 읽습니다.
`file:///`로 연 경우에는 폴더를 읽을 수 없으므로 **Load episode** 안의
**Open a JSON file instead**로 저장해 둔 JSON을 직접 여세요.

## 에피소드 넘기기

헤더의 **&lsaquo; Prev** / **Next &rsaquo;** 로 체크리스트 순서대로 앞뒤 에피소드로 넘어갑니다.
1티어 20번에서 Next를 누르면 21번이 바로 에디터에 올라옵니다. 버튼 사이의 `20 / 506`이 지금 위치입니다.

에디터의 오류번호를 기준으로 찾으므로, Load episode로 아무 데나 뛰어든 다음 거기서부터 Next로 이어가도 됩니다.
목록은 처음 한 번만 읽어 두고 다시 쓰기 때문에 넘길 때마다 새로 받지 않습니다.
끝에 닿으면 더 넘어가지 않고 그 사실을 알려 줍니다.

## 버그 이미지 AI 생성

### 이미지 API로 만들기

`index.html`의 **Generate bug with AI** 버튼으로 새 버그 PNG를 바로 만들 수 있습니다.
컨셉은 기존 CS1002 버그와 동일하게 고정되고, 오류별 모티브와 아주 작은 바리에이션만 달라집니다.

1. 이미지 API를 고릅니다. OpenAI `gpt-image-1` 또는 Google `gemini-2.5-flash-image`를 지원합니다.
2. 본인 API 키를 붙여넣습니다. 키는 이 탭의 sessionStorage에만 남고 해당 API로만 전송됩니다.
3. Variation에서 바리에이션을 고릅니다. Auto는 오류번호에 따라 네 가지 중 하나를 고정적으로 선택합니다.
4. 필요하면 Bug concept를 직접 적습니다. 비워 두면 `오류번호 — 오류 메시지`가 사용됩니다.
5. Generate bug를 누르면 생성된 PNG가 미리보기와 프로젝트에 바로 적용됩니다. Save PNG로 `assets` 폴더에 보관할 수 있습니다.

`Use the CS1002 bug as reference`를 켜 두면 기존 CS1002 이미지를 스타일 참조로 함께 보내 화풍이 유지됩니다.
OpenAI는 투명 배경 PNG를 그대로 반환하고, Gemini처럼 불투명 이미지를 반환하는 경우에는
바깥쪽 단색 배경을 자동으로 지워 실제 알파 채널을 만듭니다. 단색 배경이 아니면 다시 생성하도록 안내합니다.
API 호출은 브라우저에서 직접 일어납니다. `file:///`에서 차단되면 `START_STUDIO.bat`으로 열어
`http://127.0.0.1:8765`에서 다시 시도하세요.

## 깃허브 액션으로 렌더

`episodes` 폴더의 JSON이 `main`에 커밋되면 `.github/workflows/render.yml`이 자동으로 돕니다.
내 PC를 켜 둘 필요가 없고, 결과물은 로컬에서 렌더한 것과 같은 `render.py` 출력입니다.

페이지의 Render MP4 버튼이 이 과정을 대신 해 줍니다. 버튼이 하는 일은 아래와 같습니다.

1. 에피소드 JSON과 버그 PNG를 커밋 하나로 저장소에 올립니다. JSON의 `bug`는 `../assets/<오류번호>.png`입니다.
2. `Render episodes` 워크플로를 그 오류번호로 실행합니다.
3. 액션이 `episode-<오류번호>` 릴리스에 MP4와 LOCKED 썸네일을 올립니다.
4. 페이지가 완성된 MP4를 `C# QUIZ - ERROR <오류번호>.mp4` 이름으로 내려받습니다.

## 다운로드 파일 이름

받는 파일은 `C# QUIZ - ERROR CS0000.mp4`, 썸네일은 `C# QUIZ - ERROR CS0000-locked.png`입니다.
그대로 유튜브에 올리면 제목 칸이 이 이름으로 채워집니다.

콜론은 쓰지 않습니다. 윈도우 파일 이름에 넣을 수 없는 문자라 `START_STUDIO.bat`으로 렌더하면
파일을 만들지 못하고, 브라우저도 다운로드 이름에서 지웁니다. 그래서 `:` 자리에 `-`를 씁니다.

깃허브 페이지에서 받을 때는 **릴리스 자산 이름이 그대로 파일 이름이 됩니다.** 릴리스 파일은 다른
출처에 있고 CORS 헤더가 없어서(OPTIONS는 405) 페이지가 내용을 읽어 이름을 붙일 방법이 없습니다.
깃허브는 자산 이름에서 허용하지 않는 문자를 바꾸므로 `#`이나 공백이 점으로 바뀔 수 있습니다.
페이지는 이름을 예측하지 않고 릴리스에서 읽어 오므로, 깃허브가 어떻게 저장하든 내려받기는 동작합니다.

이미 렌더해 둔 에피소드의 이름을 바꾸려면 `Rename release assets` 워크플로를 수동으로 한 번
실행하세요. 다시 렌더하지 않고 이름만 바꿉니다.

손으로 할 때도 같습니다. 대화창의 Save project로 받은 JSON을 `episodes/`에, PNG를 `assets/`에
넣고 커밋하면 액션이 돕니다.

바뀐 JSON과 PNG에 해당하는 에피소드만 렌더합니다. `render.py`를 고치면 전부 다시 렌더합니다.
Actions 탭에서 `Render episodes`를 수동 실행할 수도 있고, 오류번호를 적으면 그것만, `all`이면 전부 렌더합니다.
액션은 렌더가 끝나면 `episodes/index.json`도 갱신해 커밋하므로 페이지 목록에 바로 나타납니다.

### 500 Failed to run workflow dispatch

깃허브의 워크플로 수동 실행 API가 간헐적으로 500을 돌려줍니다. 토큰이나 권한 문제가 아닙니다.

그래서 Render MP4는 이 API를 쓰지 않습니다. 에피소드를 저장하는 커밋이 `episodes/*.json`과
`assets/*.png`를 건드리고, 그게 워크플로의 push 트리거라서 **커밋 자체가 렌더를 시작**합니다.
페이지는 그 커밋의 실행을 찾아 지켜봅니다.

수동 실행이 필요한 경우는 하나뿐입니다. 에피소드가 직전과 완전히 같아서 커밋할 내용이 없을 때인데,
이때는 이미 릴리스에 올라가 있는 MP4를 그대로 내려받으므로 실행 자체를 건너뜁니다.

그래도 500을 보게 되면, 에피소드는 이미 커밋된 상태입니다. Actions 탭에서 실행이 도는 것을
확인하고 몇 분 뒤 Render MP4를 다시 누르면 완성된 MP4를 받아 갑니다.

## 배경음

`music` 폴더에 넣어 둔 곡 중에서 에피소드마다 하나를 고릅니다. 에디터의 **Music list** 버튼에서 관리합니다.

- **None** 은 효과음만 넣습니다.
- **Random** 은 오류번호로 곡을 정합니다. 아래 공식이라 같은 오류번호는 언제 렌더해도 같은 곡이 나옵니다.
  기본값이라 따로 고르지 않으면 이렇게 동작합니다. JSON에 `music`이 없는 에피소드도 같습니다.
- 곡 이름을 직접 고르면 그 곡으로 고정됩니다.

**Add a track** 로 파일을 올리면 `music` 폴더에 저장되고 목록에 바로 나타납니다. 각 줄의 ✕ 로 지웁니다.
`START_STUDIO.bat` 에서는 폴더에 바로 쓰고, 깃허브 페이지에서는 저장소에 커밋합니다.
페이지에서 추가하거나 지우려면 Render MP4 창의 토큰이 먼저 들어가 있어야 합니다.

고른 곡은 에피소드 JSON의 `music` 필드에 남고, 렌더할 때 효과음 아래에 깔립니다.
앞뒤로 페이드가 들어가고, 곡이 12초보다 짧으면 이어 붙여 채웁니다. 음량은 `render.py`의 `MUSIC_GAIN` 입니다.
미리보기에서도 같은 곡이 같은 음량으로 재생됩니다.

### Random 공식

곡마다 `FNV-1a(오류번호 + "|" + 파일이름)` 값을 구해 가장 큰 곡을 씁니다. 값이 같으면 파일 이름이 뒤인 쪽입니다.
`render.py`의 `track_for`와 `studio.js`의 `pickRandom`이 같은 해시를 씁니다. 미리보기에 뜬 곡이 렌더 결과와 같습니다.

점수가 오류번호와 그 곡 이름에만 달려 있어서, 다른 곡을 더하거나 빼도 나머지 배정은 그대로입니다.
곡을 지우면 그 곡을 쓰던 오류번호만 다른 곡으로 옮겨 갑니다. 곡을 추가하면 새 곡이 이기는 몇 개만 바뀝니다.
어떤 경우에도 움직이지 않게 하려면 Random 대신 곡 이름을 직접 고르세요. 그 이름이 JSON에 그대로 남습니다.

폴더에 넣는 곡은 본인이 사용 권리를 확보한 것이어야 합니다. 유튜브 저작권 정책은 본인 책임입니다.

## 렌더할 때 자동 아카이브

`START_STUDIO.bat`에서 Render MP4를 누르면 렌더 직전에 현재 에피소드가 자동으로 보관됩니다.

- `episodes/<오류번호>.json` — 편집한 내용 그대로. 버그 경로는 `../assets/<오류번호>.png`
- `assets/<오류번호>.png` — 지금 쓰고 있는 버그 이미지
- `episodes/index.json` — 목록 갱신

따로 저장하지 않아도 다음에 Load episode에서 바로 다시 불러올 수 있습니다.
같은 오류번호로 다시 렌더하면 두 파일을 덮어씁니다. 기존 에피소드를 보존하려면 오류번호를 다르게 하세요.
렌더 결과 MP4와 썸네일은 `output` 폴더에 남고, 이 폴더는 깃에 올라가지 않습니다.

## 썸네일

미리보기 아래의 **Download LOCKED thumbnail** 버튼이 1080×1920 썸네일을 바로 저장합니다.
영상의 한 장면을 캡처하는 것이 아니라 썸네일 전용 레이아웃으로 그립니다.

- 버그는 검은 실루엣으로 두고 형광 라임 테두리 발광을 입힙니다. 정체를 가려 클릭을 유도하는 구성입니다.
- 도트 그리드 배경, 모서리 십자 표시, 대괄호 프레임, 상단 `LOCKED`, 하단에 큰 오류번호가 들어갑니다.
- 오류 메시지는 넣지 않습니다. 작은 화면에서 읽히지 않고 번호가 묻힙니다.

`render.py`도 같은 디자인으로 `<오류번호>-bug-archive-locked.png`를 만듭니다.
액션이 릴리스에 올리는 썸네일과 버튼으로 받는 썸네일이 같습니다.

## 터미널 사용법

```bash
python -m pip install -r requirements.txt
python render.py episodes/CS1002.json
python render.py episodes/CS1002.json --bug assets/another-bug.png
python render.py --batch episodes
python render.py episodes/CS1002.json --preview
```

`--output`으로 MP4 경로, `--output-dir`으로 출력 폴더를 지정할 수 있습니다.
시스템 FFmpeg가 있으면 사용하고, 없으면 imageio-ffmpeg의 실행 파일을 사용합니다.
폰트와 버콜 표정 5종, CS1002 버그 샘플은 포함되어 있습니다.

## 자동 처리되는 것

- 수정 전·후의 차이를 감지하고 정답 부분을 강조합니다.
- 버그 출현 위치와 버콜의 포인터를 해당 수정 위치로 이동합니다.
- 코드와 줄 번호에 같은 글자 크기·기준선을 적용합니다.
- 오류 점·번호·구분선·메시지의 세로 중심을 맞춥니다.
- 카운트 숫자를 진행 바의 중심 높이에 맞춥니다.
- 긴 코드의 글자 크기를 조절하고, 긴 오류 메시지는 최대 두 줄로 조판합니다.
- 오류번호와 메시지를 엔딩 도감에 자동 반영합니다.
- TTS 없이 동일한 효과음과 동작 순서를 유지합니다.
- 라이브 프리뷰에서도 MP4와 같은 효과음을 같은 시점에 들려줍니다. 미리보기 위의 Sound 체크박스로 끌 수 있고, 브라우저 정책상 Play를 누른 뒤부터 납니다.
- 렌더링 시 주요 장면 미리보기와 정렬 수치 `layout.json`을 함께 출력합니다.

## 입력 범위

짧은 모바일 퀴즈용으로 코드 1~6줄을 지원합니다. 너무 긴 코드나 오류 메시지는 잘라내지 않고 입력 수정을 요청합니다.
버그는 배경이 실제로 투명한 PNG여야 합니다. 체크무늬가 그려진 불투명 파일은 사용할 수 없습니다.
일괄 제작 시 각 JSON의 오류번호는 서로 달라야 합니다. 동일한 출력 경로로 다시 실행하면 MP4를 갱신합니다.
실제 코드의 컴파일과 오류번호 검증은 이 도구의 기능에 포함되지 않습니다.
이 도구는 업로드용 MP4 제작까지 자동화하며, 유튜브 게시 기능은 포함하지 않습니다.

## 고정 타임라인

0–3초 문제 → 3–6초 카운트·고민 → 6–7.5초 수정 → 7.5–10초 버그 포획·수집 → 10–12초 도감 해금.

마지막 도감 카드는 화면 위쪽에 놓입니다. 세로 53% 아래가 비어 있어서 유튜브 퀴즈 스티커를
그 자리에 붙여도 오류번호와 메시지를 가리지 않습니다. 위치는 `render.py`와 `studio.js`의
`CODEX_LIFT` 한 값으로 맞춰져 있습니다.

영상 수정 이후에는 이 도구의 render.py와 assets를 기준으로 다음 영상을 제작하면 됩니다.
